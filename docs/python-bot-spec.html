1. プログラム概要

プログラムの目的

Twitchチャンネル rukalun のチャットを監視し、視聴者向けコマンド応答、 配信開始通知、コメント統計、クリップ紹介、Raid時のshoutoutを自動化する。

主な処理内容

TwitchIOでチャットへ接続し、twitchAPIでHelix APIを呼び出す。 Discord Webhook通知、DLsiteランキング取得、OAuthトークン更新、Git更新検知、プロセス再起動も同一プロセス内で扱う。

実行単位

asyncio.run(main()) で起動し、Twitch Botの非同期処理と、 Git更新/定期再起動用のデーモンスレッドを並行稼働させる。

3. 処理フロー（シーケンス）

3.1 起動シーケンス

  1. Config が `.env` を読み込み、Twitch/Discord/状態管理設定を構築する。
  2. GitManager.pull_and_restart_if_updated() が起動直後にGit更新を確認する。
  3. GitHub更新監視スレッドと定期再起動監視スレッドをdaemonとして起動する。
  4. get_valid_access_token() がTwitch access tokenを検証し、無効ならrefreshを試みる。
  5. Bot を生成し、initialize() でHelix APIのユーザー認証を設定する。
  6. bot.start() でTwitch IRCへ接続し、event_ready で配信監視とkeep-aliveタスクを開始する。

3.2 チャットコマンド処理

  1. Twitch IRCから event_message が呼ばれる。
  2. Bot自身のechoメッセージなら、削除予約対象か確認して終了する。
  3. 空メッセージは無視する。
  4. プレフィックス ! で始まる場合はコマンドとして扱う。
  5. コマンドでない場合はコメント風速・総コメント数へ記録し、`.env` に保存する。
  6. handle_commands に渡し、該当する @commands.command メソッドを実行する。
  7. 各コマンドは必要に応じてトークン検証、外部API呼び出し、クールダウン更新、チャット返信を行う。

3.3 配信監視・Discord通知

  1. monitor_stream_status が180秒ごとに get_streams を呼ぶ。
  2. 配信中かつ前回状態がオフラインなら配信開始として扱う。
  3. コメント計測状態を初期化し、StreamTitleNotifier.notify_if_needed を呼ぶ。
  4. 直前タイトルと異なる場合だけDiscord Webhookへ通知する。
  5. 配信が見つからず前回状態がライブなら配信終了として扱い、コメント計測をリセットする。
  6. 認証エラーが連続した場合はトークン更新を試みる。

3.4 Clipコマンド処理

  1. !clip または !myclip が呼ばれる。
  2. 実行者が CLIP_SPECIAL_USERS でなければ30分クールダウンを確認する。
  3. クールダウン中なら残り時間を返信し、リキャスト復帰通知を予約する。
  4. 実行可能ならTwitch clips APIから最大100件のClipを取得する。
  5. !myclip は実行者ID/名前で作成者フィルタを適用する。
  6. 候補からランダムに1件選択しURLを返信する。
  7. 一般ユーザーの場合は最終実行時刻を `.env` に保存し、復帰通知を予約する。

3.5 自動復旧・再起動

  1. keep_alive が45秒ごとにWebSocket状態と最終アクティビティを確認する。
  2. 異常を検知した場合、重複しないよう delayed_reconnect を起動する。
  3. 再接続試行が上限に達した場合は GitManager.restart_process でプロセスを再起動する。
  4. 2時間ごとに高度なトークンリフレッシュを実行し、Helix認証を再設定する。
  5. Git更新監視スレッドはリモート差分を検出し、pull後に再起動判定へ進む。
  6. 定期再起動監視スレッドは24時間経過または保留更新を見てプロセス再起動する。

4. 特記事項

外部API・ライブラリ依存

  • twitchio==2.9.0: Twitch IRC接続、コマンド処理。
  • twitchAPI==4.2.1: Helix API、OAuth、Shoutout、Clip、チャット削除。
  • discord-webhook: Discord Webhook通知。
  • requests: Twitch OAuth token API、DLsiteランキング取得。
  • python-dotenv: `.env` 読み込み。
  • aiofiles: 依存関係として定義。現行コードでは主要処理に未使用。

永続化ファイル

  • .env: 認証情報、コマンド状態、コメント状態、クールダウン時刻。
  • .env.bak: `.env` 更新前バックアップ。
  • .env.tmp: atomic更新用一時ファイル。
  • last_restart.txt: 最終再起動時刻。
  • logs/bot_YYYY-MM-DD.log: 実行ログ。

エラーハンドリング

発生箇所 検知条件 対応
トークン検証 validate APIが401、またはlogin欠落 高度リフレッシュを試行し、必要に応じてフォールバック再認可。
配信監視 TwitchAuthorizationException が連続発生 最大5回でトークン更新し、Helix認証を再設定。
Discord通知 Webhook URL未設定、送信例外 警告/エラーログを出力し、Bot自体は継続。
manga取得 HTTPエラー、HTMLから作品名を抽出できない エラーログを出し、再試行案内メッセージを返信。
manga返信削除 send_chat_message失敗、message_id未取得、delete API失敗 ctx.send と /delete コマンドへフォールバック。
WebSocket 接続断、5分間無活動、接続オブジェクト異常 遅延再接続を起動し、上限到達時はプロセス再起動。
Git更新 fetch/pull/rev-list失敗 エラーログを出し、監視スレッドは5分後に再試行。
セキュリティ上の注意: .env にはTwitch/Discordの認証情報が含まれるためGit管理しない。 トークン更新時は update_env_file がバックアップを作成し、空ファイル化時はバックアップから復旧する。
