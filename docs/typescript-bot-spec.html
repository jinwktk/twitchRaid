TypeScript版 Twitch Bot システム仕様書

現行稼働中の TypeScript 版 twitchRaid Bot の機能設計書。 Twitchチャット、配信監視、Discord通知、配信まとめスレッド、Clipキャッシュ、 Raid shoutout、ゲーム時間集計、Git自動更新、PM2再起動までを対象に整理する。

1. プログラム概要

プログラムの目的

Twitchチャンネル rukalun のチャットと配信状態を監視し、 視聴者向けコマンド応答、配信開始通知、配信まとめ、Clip投稿、Raid対応を自動化する。

主な処理内容

TwurpleでTwitch IRC/Helix APIへ接続し、Discord Bot API/Webhookへ通知する。 ClipはSQLiteへキャッシュし、配信中は新規Clipをまとめスレッドへ随時投稿する。

実行・運用

src/index.ts が起動入口。PM2管理下ではGit更新後に npm run build を実行し、process.exit(0) で再起動する。

3. 処理フロー（シーケンス）

3.1 起動シーケンス

  1. src/index.ts が Config、GitManager、SystemWatcher を生成する。
  2. 起動直後に git pull を確認し、更新があれば npm run build 後に再起動する。
  3. Git更新監視と定期再起動監視を開始する。
  4. getValidAccessToken でTwitch tokenを検証し、必要ならrefreshする。
  5. Bot.start() が RefreshingAuthProvider、ApiClient、Clip同期器、ChatClient を初期化する。
  6. Chat接続完了後、keep-aliveと配信監視タイマーを開始する。

3.2 チャット・コマンド処理

  1. ChatClient.onMessage がチャンネル、ユーザー、本文、メッセージメタデータを受け取る。
  2. 本文が ! で始まる場合はコマンドとして _handleCommand へ渡す。
  3. 通常コメントの場合は CommentSpeedMeter に記録し、30秒デバウンスで `.env` に保存する。
  4. コマンドは switch で各ハンドラへ分岐し、必要な外部APIやSQLiteを参照する。
  5. 返信は chatClient.say またはBot API経由で送信する。

3.3 Clip同期・Clipコマンド

  1. 起動時に ClipCacheSynchronizer.start() が直近同期と全期間バックフィルを開始する。
  2. 1分ごとに直近60分のClipを同期し、配信中なら新規Clip投稿処理を呼ぶ。
  3. !clip / !myclip はSQLiteキャッシュから履歴未表示Clipを優先選択する。
  4. キャッシュに候補がない場合のみ、Twitch Clip APIを最大1000件までページング取得する。
  5. 一般ユーザーは30分クールダウンを保存し、復帰時にリキャスト通知を送る。

3.4 配信通知・まとめスレッド

  1. 配信監視が180秒ごとに getStreamByUserName を呼び、開始/終了を検知する。
  2. 開始時は stream-summary-state.json に active stateを保存する。
  3. Discordへ開始通知を投稿し、投稿IDからスレッドを作成して threadId を保存する。
  4. 直近Clip同期後、未投稿Clipをスレッドへ投稿し、postedClipIds を更新する。
  5. 終了検知時は配信時間帯のClipを最終同期し、未投稿Clip、終了まとめを投稿してスレッドをアーカイブする。
  6. !streamnotify は手動で開始通知を強制投稿し、その投稿から作られたスレッドを優先する。

3.5 自動更新・復旧

  1. SystemWatcher が10分ごとに GitManager.checkForUpdates を実行する。
  2. 更新がある場合は git pull、npm run build、即時PM2再起動を行う。
  3. 5分ごとに再起動間隔を確認し、24時間経過または保留更新があれば再起動する。
  4. Chat切断時は最大10回まで遅延再接続し、上限到達時はプロセス再起動する。
  5. keep-aliveは45秒ごとにリキャスト通知と2時間ごとのtoken refreshを処理する。

4. 特記事項

外部API・ライブラリ依存

  • @twurple/chat: Twitchチャット接続、onMessage/onRaid/onDisconnect。
  • @twurple/api: Streams、Clips、Videos、Users、Shoutout、Chat message delete。
  • @twurple/auth: RefreshingAuthProviderとユーザーコンテキスト切替。
  • node:sqlite: Clipキャッシュ、履歴、走査状態の保存。
  • dotenv: `.env` 読み込み。
  • winston / winston-daily-rotate-file: 日次ローテーションログ。
  • Discord REST API: Bot投稿、Webhook投稿、メッセージ起点スレッド作成、スレッドアーカイブ。
  • Twitch GraphQL: !boom のVODチャプター/メタデータ取得。
  • DLsiteランキングHTML: !manga の作品タイトル取得。

永続化ファイル

  • .env: Twitch/Discord認証情報、コマンド状態、コメント状態。
  • .env.backup: `.env` 更新前バックアップ。
  • data/clips.sqlite: Clipキャッシュ、履歴、走査窓、同期state。
  • data/stream-summary-state.json: 配信まとめ状態。
  • last_restart.txt: 再起動クールダウン時刻。
  • logs/bot_YYYY-MM-DD.log: Botログ。

エラーハンドリング

発生箇所 検知条件 対応
OAuth token validate 401、refresh失敗、token欠落 refresh APIを試行し、失敗時はログ出力。起動時は最大10回リトライ。
Chat切断 Twurple onDisconnect 15〜60秒で最大10回再接続し、上限到達でPM2再起動。
Discord Bot投稿 403などのBot API失敗 Webhook URLがあればWebhookへフォールバック。スレッド作成はBot権限に依存。
配信まとめ 投稿途中失敗、再起動、threadId欠落 stateをJSON保存し、次回監視で再試行。開始通知IDからスレッド作成を再試行。
Clip同期 Twitch API失敗、過密期間、削除済みClip 警告ログ、期間分割、日次再走査で unavailable_at を反映。
manga取得/削除 DLsite取得失敗、Bot API削除失敗 エラー返信、chatClient.say fallback、ログ出力。
Git更新 fetch/pull/build失敗 ログ出力。更新後再起動はクールダウン対象外で即時実行。
セキュリティ上の注意: .env にはTwitch/Discordの機密情報が含まれるためGit管理しない。 Bot Tokenにはメッセージ投稿、スレッド作成、スレッドアーカイブに必要なDiscord権限が必要。
